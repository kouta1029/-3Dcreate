Blender 4.3.2 の Eevee、16サンプル、黒背景、24 fps、全120フレーム。無文字・無透かし。Phase 1 の全体側面カメラ `QC | whole loop` を両シーンで使用した。まず 960×540 のプレビューを確認し、本番は PNG 連番から FFmpeg で H.264 MP4 に変換した。代表 PNG はいずれもフレーム61。

A1 では手前側の欄干パネルだけを完全に透明にし、手摺りベルトと Phase 1 のトラス透過を維持した。A8 では奥側の欄干、スカートガード・インレット部、スラブ、乗降板・櫛板の不透明度を下げ、トラスの透過率を86%から96%に上げた。踏段、前輪・後輪、踏段チェーン、駆動チェーンと駆動部を不透明で描き、スプロケット、手摺り駆動部とチェーンを発光で強調した。

1080p の事前計測から、PNG 連番120枚を A1 は約83分、A8 は約81分と見積もった。 両シーンを本番解像度1920×1080で描画した。

フレーム単価は Blender の連番レンダー開始または直前の PNG 保存完了から、当該 PNG 保存完了まで。合計は各シーンの連番レンダー処理全体で、プレビューと見積もり用のレンダーを除く。レンダラーの動作確認は Eevee のヘッドレス描画で実施した。

## QC

- 両方の `.blend` で、全メッシュの頂点座標と面コーナーの頂点インデックス、およびフレーム1・10・61・120の全オブジェクトの変換行列が Phase 1 と一致した。
- FFprobe で H.264、24 fps、120フレーム、各5.000秒を確認し、FFmpeg で全フレームをデコードした。
- Phase 1 の5秒周期を使用した。踏段列は6踏段分（踏段チェーン36リンク分）進み、送り側から上下の反転部を通って戻り側へ循環する。書き出し範囲はフレーム1〜120。フレーム121はループ閉じの比較に使用した。
- A1 の見積もり用 1080p PNG で、フレーム1と121のRGB平均絶対差は 0.0004/255。本番 PNG の隣接コマの同差は119→120で 0.8018/255、120→1で 0.7962/255、1→2で 0.7905/255。
- A8 の見積もり用 1080p PNG で、フレーム1と121のRGB平均絶対差は 0.0004/255。本番 PNG の隣接コマの同差は119→120で 1.0224/255、120→1で 1.0137/255、1→2で 1.0078/255。

## 推測箇所と参照からの逸脱

- Phase 2 で選んだ透過率と発光は、内部を読み取りやすくするための描画上の設定。新規の機構形状や寸法の推測はない。
- JP6585230B1 を優先した配置と、JP3704363B2 に基づく前後の案内レール・反転部を引き継いだ。Phase 1 の模式寸法、30歯のスプロケット、0.4896 m/s の描画速度、緩和区間の最大約2 mmの踏面・ライザー重なりについては [Phase 1 レポート](../REPORT.md) を参照。
- 手摺りの駆動ローラとスプロケットの回転、および踏段チェーンのリンク移動は Phase 1 の既存アニメーションを使用した。手摺りベルト本体と駆動チェーンのリンク移動は Phase 1 と同様に静止表示。

## 再描画

リポジトリルートから [render_a.py](render_a.py) を実行する。Blender 4.3.2 と FFmpeg を使用し、第2引数には PNG 連番と計時 CSV を保存する作業ディレクトリを指定する。

```sh
blender -b production/escalator_phase1.blend --python-exit-code 1 \
  --python production/phase2/render_a.py -- a1 /tmp/phase2-a1
blender -b production/escalator_phase1.blend --python-exit-code 1 \
  --python production/phase2/render_a.py -- a8 /tmp/phase2-a8
```
