# フェーズ2 共通仕様（タスクA〜D 全員必読）

## 開始手順（必須）
1. チェックアウトは初期コミットから始まるので `git checkout main` で最新の main に切り替える（フェーズ1の成果物と参照PDFは main に含まれている。fetch_references.sh の実行は不要）
2. 読むもの: `AGENTS.md`、`MECHANISM_EP1_ESCALATOR_DESIGN.md`、`production/REPORT.md`（フェーズ1報告書）、`production/phase2/PLAN.md`、自分の担当ファイル `production/phase2/TASK_X.md`
3. Blender はプリインストールの 4.3.2 を使う

## 土台
- `production/escalator_phase1.blend` と既存スクリプト（build_escalator.py / track.py）を土台にする。モデル寸法・部品配置は変更しない（カメラ、材質の透明度、アニメーション追加のみ）
- 新規スクリプトは `production/phase2/` に置く

## 描画の共通設定
- 1920×1080、24fps、Eevee、16サンプル、背景は黒（機構ショット）
- 部品の色分けはフェーズ1を維持: ステップ=灰＋黄線、車輪=青、駆動部=橙。解説対象の部品は発光で強調してよい
- 映像内に文字・ラベル・透かしは入れない
- **欄干の修正（フェーズ1 QC の指摘）**: 機構ショットでは手前側の欄干パネルを完全に透明化または非表示にし、傾斜部のステップが見えるようにする。手すりベルト自体は残す。トラスの半透明はフェーズ1同様でよい
- ループするシーンは継ぎ目なく繰り返せること（周期 4.8秒 = 115.2フレームに近い 120フレーム=5秒で閉じるフェーズ1の方式に合わせる）

## 時間対策（重要）
- まず PNG 連番で描き、最後に ffmpeg で MP4 化する
- 1シーンの見込みが2時間を超える場合は、そのシーンを 1280×720 に落として描き、レポートに明記する（失敗するより落とす）
- 途中でコミットできる単位（シーン単位）で進め、終わったシーンから成果物に含める

## 納品
- 成果物: `production/renders/` に担当シーンの MP4（ファイル名は各 TASK 指定）、代表静止画 PNG 各1枚、`production/phase2/REPORT_X.md`（実測: フレーム単価・合計時間、推測箇所、参照からの逸脱、解像度を落とした場合はその旨）
- 終わったらブランチ `phase2-x`（x は担当記号の小文字）に push し、main 宛ての PR を作る。マージはしない
- 担当外のシーンには手を出さない（並行タスクと競合するため）
