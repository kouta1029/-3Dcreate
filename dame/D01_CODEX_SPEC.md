# Codexへの依頼書 ― 「ダメにはワケがある」D01 アルミホイル×電子レンジ 3D制作

---

あなたは Blender を使った3D制作担当です。以下の仕様で、YouTube Shorts 用の3D素材を制作してください。**今回のタスクはフェーズA（モデル構築とテストまで）です。本番レンダー（フェーズB）は次回以降の別タスクなので、勝手に進めないでください。**

## 開始手順（毎回必須・Codex Cloud の環境の都合）
1. チェックアウトは初期コミットから始まるので、最初に `git checkout main` で最新の main に切り替えること
2. `bash dame/references/fetch_references.sh` を実行し、参照画像5点を取得すること
3. `dame/` フォルダの本書（D01_CODEX_SPEC.md）と `dame/references/REFERENCE_INDEX.md` を必ず読んでから着手すること
4. Blender はプリインストール済みの 4.3.2 を使う（新規インストールは不要）。`blender --version` で確認すること

## 環境確認
1. Blender がヘッドレスで起動し、Eevee で1フレーム書き出せることを確認してください（検証済み：この環境では Eevee のヘッドレス描画が動作します）。Eevee が使えない場合は、その旨と代替案を報告してから進めてください

## プロジェクト概要（何のための素材か）
- 縦型 Shorts（1080×1920、41秒）の第1話。テーマは「アルミホイルを電子レンジに入れると、なぜ火花が出るのか？」
- 3D素材は動画の 0〜27秒で使います。構成は次のとおりです：
  - 0–4秒：庫内でホイル包みが回り、包みの縁が赤熱していく（火花と炎は編集側で重ねるため、3Dでは作りません）
  - 4–8秒：平らなホイルとシワくちゃのホイルの対比（静止画）
  - 8–14秒：電子レンジの断面（静止画）＋編集側の図解
  - 14–21秒：シワくちゃホイルのマクロ映像（カメラが先端へ寄る）
  - 21–27秒：0–4秒の素材を流用
- ナレーション（尺と空気感の参考。音声は別工程）：
  1. アルミホイルを電子レンジに入れると、火花が飛ぶことがあります。
  2. でも、金属を入れたら、必ず火花が出るわけではありません。
  3. 電子レンジは、マイクロ波で食品の水を振動させ、熱に変えます。
  4. 金属はマイクロ波を反射し、表面では電子が激しく動きます。
  5. ホイルのシワや尖った部分では、その働きが一点に集中します。
  6. 集中した電界が空気の絶縁を破ると、火花が飛びます。これが放電です。
  7. 実際に、ホイルで包んだサツマイモが発火した事故も、報告されています。
  8. 火花は、発火や故障のきっかけになります。
  9. 温めるときは、説明書で使える容器かどうかを、まず確認してください。

## 制作物（モデル）

寸法は実機そのものではなく、見え方が正しく伝わる代表モデルで構いませんが、比率は下記の目安に合わせてください。

### M1 電子レンジ本体
- 外形の目安：幅480×奥行360×高さ290mm（一般的な単機能〜オーブンレンジ級）
- 構成：本体外観（ドア開閉可）、庫内（内寸の目安 幅310×奥行330×高さ210mm、ターンテーブル径270mm、庫内灯）、操作パネル（ボタンとダイヤルの形状のみ。**文字や数字は入れない**）
- ドアには金属メッシュ（細かい網目）の質感を入れること。庫内を見せるショットではドアを開けた状態／外した状態も使えるようにすること
- 断面バリエーション：側面をカットして庫内とマグネトロン側の導波口が見える状態を、コレクション切り替え等で再現できる構造にすること

### M2 ホイルで包んだサツマイモ
- サツマイモ（長さ約150mm・太さ約60mm、細長い紡錘形）をアルミホイルで包んだ状態
- ホイルは金属光沢を持ち、包んだときのシワとねじった端があること
- **赤熱バリエーション**：包みの縁やシワの先端が赤熱した状態を、マテリアルの発光で表現した別バリエーションも作ること（冒頭の山場用）

### M3 シワくちゃのアルミホイル（マクロ用）
- 尖った折り目・めくれた端・鋭い先端が分かる拡大モデル
- マクロ撮影に耐えるよう、折り目の形状を丁寧に作ること。実寸より誇張して構いませんが、誇張した場合はレポートに明記すること

### M4 平らなホイル＋食品
- 食品（丸みのある塊）の表面に、滑らかなホイルが密着して覆っている状態。M3との対比用
- 端が立ったり浮いたりしていない、きれいな状態にすること

### M5 台所カウンター（簡易セット）
- M1を置く設置面と背景の壁のみ。生活感のある小物・調理器具は入れないこと

## 共通レンダー仕様
- レンダーエンジン：Eevee、16サンプル
- 静止画：1080×1920（縦型）。テストレンダーは 540×960 でよい
- 動画：24fps
- 背景：濃いグレー基調。庫内は暗色。色の意味（編集側の約束事）：熱＝オレンジ、電気＝シアン、危険＝赤、安全＝緑。3D側の素材はこの色分けと喧嘩しない落ち着いた色調にすること
- **作らないもの**：火花、閃光、炎、煙、文字・ロゴ・テロップ類。これらは全て編集側で重ねます。3D側は「赤熱まで」を担当します
- カメラ規則：対象ごとに複数アングルを意識すること。全体は回転・オービット、各パーツは正面／斜め（3/4）／上／クローズアップ、単体パーツはターンテーブル回転も用意できる構えにすること

## レポートの形式（REPORT_D01.md）

## 進め方のルール
- 作業はこのタスクのブランチ内で行い、PRを作成すること。**main へはマージしない**（マージとQCは依頼側が行います）
- レンダーの前に、テスト実測から所要時間を見積もること。**1つのレンダーの見積もりが2時間を超える場合は、先に解像度を720p相当に落として、その旨をレポートに明記してから**進めること
- タスクの時間上限に当たった場合は、途中経過（モデル完成・描画途中など分かる状態）でコミットし、レポートに残作業を明記すること
- ファイル名・フォルダ名は本書の指定どおりにすること。指定の無いものは英語の小文字とアンダースコアで分かりやすく付けること
